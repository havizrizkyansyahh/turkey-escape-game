# Rank push v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v2 of "Not On The Menu!" before 2026-11-28T14:00Z. v2 adds:

- a cornering ambush;
- a visible search cone;
- callouts that name each mechanic;
- medals;
- screenshots and a source outline that show the judge all of the above.

**Architecture:** Each new rule lives in its own pure module, which the Node tests drive:

- `ambush.js` for the ambush;
- `scoring.js` for combos;
- `medals.js` for medals.

`run.js` and `farmer.js` call into them. Painters and the HUD read the state and never change it. Screenshots stay real renders of `?shot=` scenes.

**Tech Stack:** Plain ES modules, canvas 2D and Web Audio. `node --test` (Node 22) tests the simulation. `tools/simulate-runs.ts` tunes the game with a bot. `tools/capture-screenshots.ts` takes the screenshots with headless Chrome.

**Spec:** `docs/superpowers/specs/2026-11-28-rank-push-design.md`

## Global Constraints

- `game/` stays static files with no network references, no build step and no new assets.
- Every screenshot is a real render of a `?shot=` scene. There are 3 or 4 of them, each at most 256 KiB, each 1280x800 JPEG.
- `main.ts` writes byte-identical output on two runs, and `vendor/makefun-game.ts` stays unchanged.
- The simulation stays deterministic: randomness comes only from `run.random`, with the fixed 1/120 s step.
- Tuning bar: `node tools/simulate-runs.ts 60` with the good bot has 0 crashes and at least 43 of 60 escapes. With the lazy bot it is still caught before 400 m.
- Commits carry no Co-Authored-By line and no Claude attribution.

## Review Focus

- **Tom hides just before an ambush.** The farmer must give up the ambush and search the spot instead of freezing.
- **Tom runs out of feathers while cornered.** The farmer must walk to him and catch him. The run must not stall.
- **An ambush zone would cross a stage door or the finish.** No zone may be reserved there.
- **The farmer is mid-lunge or mid-throw when the zone comes up.** The ambush waits for him to be chasing, and is cancelled if Tom gets within 300 px of the zone first.
- **Old saved bests without `medals`.** `loadBest` must still return a valid `medals: []`.

**Interfaces:**
- Produces:
  - `AMBUSH_TUNING = { leadIn: 900, clearing: 760, popInset: 380, swipeReach: 118, swipeSeconds: 0.3, stunSeconds: 1.6, tumbleSeconds: 1.1, hatHopBounce: 640, cancelWithin: 300 }`
  - `reserveClearing(course, length) -> number | null`: returns the clearing's start x, or `null` if the clearing would reach within 240 px of the next stage door or the finish.
  - `planAmbush(run, dt)`: counts down `run.ambush.wait` while the farmer chases in a stage that has `ambushEvery`, and then reserves a clearing.
  - `updateAmbush(run, dt)`: runs the sequence: lead-in, shortcut, pop-out, cornering, swipe, then the outcome.
  - `startAmbush(run, { high, zoneX })`: used by tests and shots.
  - `ambushSwipeBox(farmer) -> box`:
    - high swipe: y from `GROUND_Y-128` to `GROUND_Y-38`;
    - low swipe: y from `GROUND_Y-64` to `GROUND_Y`;
    - x from `farmer.x-96` to `farmer.x+24`.
  - Events: `cornered`, `farmerSwipe`, `slippedPast`, `hatHop`, `bowledOver`.
  - Farmer fields: `farmer.ambushHigh` (boolean), and `run.ambush = { wait, zoneX, phase }`.
- Outcomes:
  - **Swipe overlaps Tom and he is not invulnerable:** `hurtTurkey`, with the popup "GRABBED! -1 FEATHER".
  - **Tom is past `farmer.x + 40`:** "SLIPPED PAST! +100", and the farmer goes to `tumble`.
  - **Tom is falling with feet between `GROUND_Y-205` and `GROUND_Y-165` within 34 px of the farmer's x:** bounce `vy = -640`, "HAT HOP! +150", `stats.hatHops += 1`, and the farmer goes to `stunned`.
  - **Tom is dashing through:** "BOWLED OVER! +120", and the farmer goes to `stunned`.
  - **Tom is knocked out while the farmer is ahead:** the farmer walks back to him and calls `onTurkeyCaught('cornered')`.
